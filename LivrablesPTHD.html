Consignes — Journal de bord final (Passe Ton Hack)

Rendu en site web (HTML/CSS) par équipes, avec 1 page par élève, publié sur GitHub Pages.

1 dépôt GitHub par équipe 1 page HTML par élève captures commentées CSS commun

1) Livrable attendu

  • Un mini-site hébergé sur GitHub Pages (URL publique).
  • 1 dépôt GitHub par équipe.
  • 1 page HTML par élève : prenom-nom.html
  • Un CSS commun : style.css
  • Un dossier assets contenant les captures (organisées par élève).
  • Une page d’accueil index.html (équipe) listant et liant toutes les pages élèves.
Objectif : produire une preuve claire de votre démarche (raisonnement, outils, obstacles, validation) grâce à des captures d’écran commentées.

2) Organisation du dépôt (obligatoire)

/
│ index.html
│ style.css
│ README.md
└─ assets/
   └─ eleves/
      ├─ prenom-nom/
      │  ├─ p1_01.png
      │  ├─ p1_02.png
      │  ├─ p2_01.png
      │  └─ ...
      └─ prenom2-nom2/
         └─ ...

Conventions de nommage

  • Fichiers HTML : minuscules, sans espaces, avec tirets → prenom-nom.html
  • Captures : p1_01.png = Problématique 1, capture 1 (puis p1_02, p2_01, ...)
  • Formats images acceptés : .png, .jpg, .webp
Interdiction : rendre un PDF/Word à la place du site. Le rendu attendu est un site navigable.

3) Page équipe : index.html

La page d’accueil doit contenir :

  • Nom de l’équipe + membres + rôles (même simples).
  • Liste des élèves avec lien vers chaque page : prenom-nom.html
  • Rappel des règles de preuve (captures commentées, pas de données sensibles).

4) Page élève : format “PROBLÉMATIQUES” (obligatoire)

Chaque page élève doit être structurée en plusieurs PROBLÉMATIQUES (une par challenge traité).

Rubriques à remplir pour chaque PROBLÉMATIQUE

  • ÉNONCÉ / Descriptif (contexte + objectif)
  • RÉSOLUTION : démarche détaillée (étapes)
  • Outil(s) / Ressource(s) utilisées
  • Difficulté(s) rencontrée(s) + correction
  • Ce que j’ai appris (3 points min.)
  • Grand Oral : ce que je peux réutiliser
  • Captures d’écran commentées (preuve)

Captures d’écran : exigences minimales

  • Au moins 3 captures par problématique (recommandé : 4–6).
  • Chaque capture doit avoir une légende : ce qu’on voit + pourquoi c’est une preuve.
  • Chaque capture doit être reliée à une étape (ex : “Étape 2”).
  • Aucune donnée sensible : mots de passe, tokens, emails privés, IP internes, etc.

Présentation des commandes/outils

Quand vous utilisez le terminal ou des commandes, elles doivent être présentées proprement en bloc code :

# Exemple (adapter)
nmap -sV 10.10.10.10
curl -I https://example.com
python3 exploit.py

5) Exigences techniques HTML/CSS

  • HTML sémantique : header, main, section, footer
  • Titres hiérarchisés : h1, h2, h3
  • Images : attribut alt obligatoire
  • Navigation : lien “retour accueil équipe” sur chaque page élève
  • CSS : un seul fichier style.css partagé par toutes les pages

6) Publication GitHub Pages (procédure)

  1. Pousser le dépôt sur GitHub (branche main).
  2. Aller dans Settings → Pages.
  3. Choisir : Deploy from a branch.
  4. Sélectionner : branch main et folder /(root).
  5. Récupérer l’URL fournie (site public) et la rendre.

7) Barème (sur 20)

Critère Attendu Points
Respect du format “PROBLÉMATIQUES” Rubriques complètes, plusieurs challenges, cohérence /6
Captures commentées Preuves claires, légendes, organisation des fichiers /6
Démarche technique Étapes, justification, résolution des blocages /4
Qualité web Navigation, HTML propre, CSS commun, alt, lisibilité /4
